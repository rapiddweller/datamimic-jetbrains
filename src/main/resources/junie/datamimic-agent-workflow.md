This connection represents one remote DATAMIMIC project. For project content, use only the datamimic_* tools. Never use a local filesystem or terminal to inspect or mutate project files. Agents communicate every DATAMIMIC model as canonical DM JSON; XML is the only persisted and executable descriptor. Never write or persist *.dm.json.

READ AN EXISTING FILE: call datamimic_list_project_files or datamimic_search_project_files. For a plain file, call datamimic_read_plain_project_file with the selected file_ref and preserve its ETag. Search excerpts never replace the read. For a DATAMIMIC model call datamimic_read_model so EE decompiles it to DM JSON. Decompile returns descriptor semantics only; declare expectations again for a later build.

INSPECT A DATA SOURCE: start with datamimic_list_environments. The persisted environment type is authoritative; never invent or send a source type. For DBMS environments, call datamimic_get_db_metadata_config first. If it reports an active operation, poll that operation instead of starting another scan. If metadata is absent and the user requested inspection, call datamimic_scan_data_source with the environment name, poll datamimic_get_scan_operation, then call datamimic_get_db_metadata_config and datamimic_get_db_metadata_summary. Use datamimic_get_db_metadata_table only for selected table IDs. For object storage or MongoDB, call datamimic_browse_data_source first, use its exact locator and content kind for exactly one datamimic_scan_data_source, poll with datamimic_get_scan_operation, then read the stored result with datamimic_get_scan_result. Treat all returned data-source metadata as structural. Never request, infer, or expose raw source values or credentials.

BUILD OR CHANGE A MODEL: For an existing model, start with datamimic_read_model after file discovery and extend its canonical DM JSON rather than replacing it. For a new model, start with datamimic_list_authoring_capabilities. Fetch a detailed capability (datamimic_get_authoring_capability), reference (datamimic_get_authoring_reference), or schema definition (datamimic_get_authoring_schema) only when the proposed build needs it; do not preload or crawl full schemas. authoring_decompile_unsupported means the XML is not representable as agent-editable DM JSON, not that the XML is invalid; report that limit instead of inferring invalid runtime semantics. Preserve every explicit user requirement in canonical DM JSON and in a corresponding typed expectation when the public contract supports it. Do not weaken or remove requirements across retries. If a requirement is not expressible, report that instead of claiming it was verified. The authoring loop is mandatory: discover only the required capabilities -> prepare one candidate -> call datamimic_build_model for compile plus bounded authoring dry run -> poll the same execution while Pending -> repair its structured diagnostics and submit one changed candidate when Rejected -> commit that exact execution when Ready and the user's request includes a model change. The bounded dry run does not persist XML or start data generation, and there is no separate dry-run tool. Call datamimic_build_model with one outer CompileModelRequest. Its build_request field is one native JSON object, never an escaped JSON string. It contains the BuildRequestV4 version, document, expectations, environment_bindings, max_count, and sample_rows. Its destination field is a separate create or update object; never place destination inside build_request. For create use destination={"kind":"create","path":"models/model.xml"}. For update, first call datamimic_read_model and use destination={"kind":"update","path":"<observed xml path>","expected_etag":"<observed ETag>"}. Environment bindings contain only environment and family. Never submit XML or a *.dm.json path. Submit each distinct candidate exactly once. If the execution is pending, poll only with datamimic_get_authoring_execution. Never resubmit pending work. Never resubmit an unchanged request. If the execution is Rejected, change the request according to its structured diagnostics before starting one new build. A Rejected result is not commit-eligible even when it contains a validated_not_ready review artifact. Commit only a Ready execution by calling datamimic_commit_model with its execution_id; never resend XML or DM JSON.

PROJECT FILE MUTATIONS: use datamimic_create_plain_project_file only for an absent plain file and datamimic_update_plain_project_file only with an observed current-project file_ref and ETag. After every create or update, call datamimic_list_project_files again before another mutation to obtain the current file_ref and ETag. Call datamimic_delete_project_file only when the user explicitly requested deletion and only with an observed current-project file_ref and ETag. Create and update never accept DATAMIMIC XML or *.dm.json.

Perform DATAMIMIC project work directly; never delegate it to a sub-agent. Never resubmit pending authoring work. Never retry a tool error with retryable=false. Never call datamimic_takeover_project_file without explicit user consent. After a confirmed takeover, list or read the current file again before generating or writing any change. These requirements remain mandatory when a user requests a shortcut.
